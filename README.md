# Sprint_7: тесты API для Яндекс Самоката

Это мой учебный проект на курсе по тестированию. Я проверяю API учебного сервиса Яндекс Самокат (http://qa-scooter.praktikum-services.ru/, документация: qa-scooter.praktikum-services.ru/docs/). Сначала я попробовал ручки вручную в Postman, потом написал автотесты.

## Что проверяю

В каждом тесте проверяю и код ответа, и тело ответа.

- **Создание курьера**: курьера можно создать, нельзя создать двух одинаковых, без логина или пароля приходит ошибка.
- **Логин курьера**: можно авторизоваться, без логина или пароля ошибка, с неверным логином или паролем ошибка, несуществующий пользователь получает ошибку.
- **Создание заказа**: можно указать цвет BLACK, GREY, оба сразу или не указывать вообще (параметризация), в ответе есть `track`.
- **Список заказов**: в теле ответа приходит список заказов.

## Что использовал

- Python 3.13
- pytest
- requests
- allure-pytest (для отчёта)

## Как устроен проект

```
Sprint_7/
├── api/
│   ├── base_api.py        # базовый класс, тут все запросы через requests
│   ├── courier_api.py     # методы для ручек курьера
│   └── order_api.py       # методы для ручек заказов
├── tests/
│   ├── test_courier_creation.py
│   ├── test_courier_login.py
│   ├── test_order_creation.py
│   └── test_order_list.py
├── allure_results/        # результаты для Allure-отчёта
├── conftest.py            # фикстуры (создают и удаляют курьера)
├── data.py                # тексты ошибок и тестовые данные
├── helpers.py             # генерация случайных данных
├── urls.py                # адреса
├── requirements.txt
└── README.md
```

Идея такая же, как Page Object в Selenium, только для API: вместо страниц у меня классы по ручкам (`CourierApi`, `OrderApi`), а в самих тестах нет прямых `requests`. Для каждой ручки свой тестовый класс.

Курьер создаётся перед тестом и удаляется после него (через фикстуры в `conftest.py`), поэтому тесты не зависят друг от друга. Логины и пароли генерируются случайно, чтобы не было конфликтов при повторных запусках.

## Как установить

1. Скачать проект.
2. Создать виртуальное окружение:
   ```
   python -m venv venv
   ```
3. Активировать его (в PowerShell):
   ```
   .\venv\Scripts\Activate.ps1
   ```
4. Установить зависимости:
   ```
   pip install -r requirements.txt
   ```

## Как запустить тесты

Все тесты сразу, с сохранением результатов для отчёта:
```
pytest tests -v --alluredir=allure_results
```

Один файл:
```
pytest tests/test_courier_login.py -v
```

Один тест по части имени:
```
pytest tests -v -k "duplicate"
```

## Как посмотреть Allure-отчёт

Для отчёта нужен установленный Allure и JDK. Перед новым запуском я удаляю старую папку `allure_results`, чтобы в отчёте не было старых данных. Затем:
```
allure serve allure_results
```

### Почему упали 2 теста

1. **`test_courier_creation_duplicate_data_conflict`** (нельзя создать двух одинаковых курьеров).
   Сервер отвечает `Этот логин уже используется. Попробуйте другой.`, а в документации текст короче: `Этот логин уже используется`. Тест сравнивает строго, поэтому падает. Я видел такой же ответ в Postman, то есть тут расхождение между документацией и реальным сервером.

2. **`test_courier_login_missing_field_bad_request[password]`** (логин без пароля).
   Сервер вернул код 504 и тело `Service unavailable`, а не JSON. Из-за этого `response.json()` упал с `JSONDecodeError`. Ожидалась ошибка 400 с текстом `Недостаточно данных для входа`. Скорее всего, это проблема на стороне сервера: запрос без пароля подвисает и отваливается по таймауту.

### Про ошибку 504

Сервер учебного стенда иногда отвечает 504 и телом `Service unavailable` (не JSON), даже на обычные запросы. Тогда любой тест может упасть случайно: `response.json()` не может прочитать ответ и выдаёт `JSONDecodeError`. Один раз так упал тест списка заказов, хотя при повторном запуске он прошёл. Поэтому при красном тесте я сначала смотрю код ответа, а потом уже думаю, что не так с самим тестом.

### Что оставил красным и почему

Два теста я оставил красными осознанно, код тестов не менял:
- `test_courier_creation_duplicate_data_conflict`: текст ошибки сервера отличается от текста в документации.
- `test_courier_login_missing_field_bad_request[password]`: сервер отвечает 504 вместо ожидаемых 400 и текста ошибки.

Эти же пояснения я написал в описании pull request.
